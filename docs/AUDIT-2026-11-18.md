# Audit technique et UX — 18 novembre 2026

Statut : audit statique du code et vérifications automatisées GitHub Actions. **Ce n'est pas une validation exhaustive sur appareil.**

## Corrections incluses en v0.1.1

| Zone | Défaut constaté en v0.1.0 | Correction |
| --- | --- | --- |
| Mise à jour interne | Une APK GitHub pouvait être présentée sans vérifier son package et son versionCode | Nom exact de l'asset, version sémantique valide, SHA-256 GitHub, vérification locale de l'APK, du package et du numéro de build avant l'installation |
| Installation | Retour du panneau « Installer les applications inconnues » entraînait un second téléchargement | Réutilisation de l'APK téléchargée dans la session, installation demandée de nouveau |
| Navigation | Le bloc d'auto-mise à jour se trouvait après jusqu'à 80 entrées d'historique | Mise à jour affichée sur l'accueil ; 3 onglets (Accueil / Historique / Paramètres) |
| Écrans larges | Liste étirée et illisible sur tablette | Largeur du contenu limitée à 760 dp et défilement indépendant de la barre de navigation |
| Historique | Pas de recherche et présentation mélangeant surveillance et réglages | Historique dédié, recherche par source/version et tri par version |
| Sources | Pas de configuration individuelle malgré le cahier des charges | APKMirror, APKPure, Google Play activables séparément |
| Notifications | Deux vérifications en parallèle pouvaient concurrencer SharedPreferences | Mutex par processus dans le moteur de suivi et annulation des tâches si aucune source activée |
| Permissions | Affichage des notifications pas immédiatement actualisé après autorisation | Recomposition après réponse de la demande de permission |
| Confidentialité | Backup Android activé par défaut | Sauvegarde automatique désactivée dans AndroidManifest |
| Livraison | Publication manuelle des futures versions | Publication signée automatique d'un nouveau numéro de version, sans écraser les releases existantes |
| Régressions | Peu de tests de stockage/versions | Tests Robolectric : première synchronisation, doublons, variantes, bêta, échecs, mode Jamais, préférences |

## Vérifications automatisées

- CI : `testDebugUnitTest`, `lintDebug` et `assembleDebug`.
- Release : tests unitaires, construction signée, `apksigner verify`, empreinte SHA-256, publication GitHub Releases.
- Identité Android conservée : `io.github.epikaigle.deezertracker`.
- Clé de production uniquement en secrets GitHub ; la clé n'est jamais ajoutée au dépôt.

## Limites non couvertes par cette validation

1. Une compilation et `apksigner verify` ne prouvent pas l'installation de l'APK ni une **mise à jour v0.1.0 → v0.1.1 sur téléphone**. Ce scénario exige un test réel.
2. APKMirror peut bloquer les flux RSS (Cloudflare/CAPTCHA). Aucun contournement n'est intégré.
3. L'endpoint d'historique APKPure n'est pas une API contractuellement stable. Son format ou ses en-têtes peuvent changer.
4. Google Play n'affiche pas systématiquement `softwareVersion` dans ses métadonnées publiques ; le connecteur peut indiquer « indisponible ».
5. Le rendu avec grands caractères, lecteurs d'écran, rotation, modes contraste, tablette et petits écrans n'a pas été inspecté visuellement sur un appareil. La mise en page a été conçue pour rester scrollable et limiter la largeur.
6. Les notifications en arrière-plan sont soumises au mode économie d'énergie et aux permissions Android : les fréquences sont approximatives.
7. Les dates de publication ne sont affichées que quand un fournisseur en transmet une ; la date de première observation n'est pas une date officielle de sortie.

## Protocole manuel à effectuer

1. Sur une installation de production v0.1.0 (pas debug), choisir le mode Jamais, enregistrer un historique et noter les paramètres.
2. Ouvrir l'écran de mise à jour après publication de v0.1.1 ; télécharger et installer sans quitter l'application (Android peut demander l'autorisation « Installer depuis cette source » puis sa confirmation).
3. Vérifier versionName 0.1.1, versionCode 2, présence de l'historique et des préférences.
4. Activer le mode 30 minutes, autoriser les notifications, confirmer qu'une nouvelle version Deezer produit au plus une notification indépendamment du nombre de sources.
5. Couper le réseau : chaque source doit afficher une erreur et conserver l'historique, sans fausse version.
6. Tester portrait et paysage sur un écran étroit, tablette, thèmes sombre/clair, agrandissement de police et TalkBack.

**Conclusion :** audit automatisé et corrections techniques réalisés ; le fonctionnement réel des sources et l'expérience sur appareil nécessitent toujours des essais utilisateur ou un banc de test Android instrumenté.
